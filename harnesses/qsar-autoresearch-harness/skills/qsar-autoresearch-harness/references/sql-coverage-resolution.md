# Native SQL scan/index foundation

`scripts/qsar_sql_coverage.py` parses every CREATE and INSERT before any scientific selection. It never executes source SQL. The SQLite schema is fixed and values are parameterized. All CREATE-derived fields, numeric lexemes, NULLs, raw tuple text, supplied column order, statement SHA-256, source line, statement ordinal and tuple ordinal are retained. Omitted INSERT columns remain NULL in the body; `columns_json` distinguishes omission from explicit NULL. DDL defaults are not applied.

`scan(source, new_index_path, source_id)` returns a full native scan profile. Empty schemas are retained. Duplicate schemas/columns, missing schemas, arity errors, unsupported literals and unsupported operations fail closed in every table. Supported source identifiers are backtick-quoted. Inert MySQL dump scaffolding is allowlisted; executable comments are conservatively restricted to single-line supported controls. Unsupported formats fail, never count as complete. Individual native lines over 8 Mi characters and buffered statement input over 16 Mi UTF-8 bytes fail as bounded resource errors; no rows are sampled or capped. Transactions commit every 5,000 tuples, SQLite cache is 8 MiB, and there is no all-row Python collection.

CLI: `python qsar_sql_coverage.py SOURCE NEW_INDEX NEW_PROFILE --source-id SOURCE_ID`. Outputs are exclusively created. Failure can leave an incomplete SQLite/profile artifact, which has no complete scan metadata and must not be accepted or reused. The scanner reads the source without modification, hashes raw source bytes before/after, and checks code bindings before publishing completion. The release remains `unknown`: a filename is not native version evidence.

`check_profile(profile)` checks fresh source/code/index bindings, embedded scan metadata, complete schema membership, row fingerprints and independently recomputed index tuple counts. It streams rows from SQLite. Forged zero counts or omitted tables fail even when the external profile and embedded metadata are updated and the index is rehashed. A coordinated rewrite of both native rows and metadata cannot be authenticated by this self-consistency check: independent full-native review remains mandatory. This function never returns scientific acceptance or resolved historical obligations.

`obligations(gaps, source_id)` derives one identity per original gap/table using UTF-8 JSON, ensure_ascii=False, sorted keys and compact separators. Each obligation ID hashes `{original_gap_sha256, table_name}` and is independent of a claimed scientific scope. Duplicate obligations fail.

Integration remains deliberately absent. Full source-wide scientific membership, typed resolutions, dictionary/fix effects, joins, anomaly dispositions, independent review envelopes and central runtime/reuse/preparation enforcement must be separately implemented and reviewed. No collection status, source hash, unknown release or consistent index closes these scientific requirements.

SQL mode controls are checked before versioned comments are discarded. Only the supported `NO_AUTO_VALUE_ON_ZERO` dump mode and terminal restoration to `@OLD_SQL_MODE` are allowed. CREATE/INSERT after an unknown restored mode fails. Other modes, including `NO_BACKSLASH_ESCAPES` and `ANSI_QUOTES`, fail in both direct statements and executable comments. Mode comments must occupy a standalone control line, avoiding ambiguous same-line state changes. Exact raw mode controls and line numbers are included in the profile; other SET controls use a fixed dump-control allowlist.

CREATE bodies use balanced parentheses and a supported column/key grammar. The suffix grammar permits only ENGINE, AUTO_INCREMENT, DEFAULT CHARSET and COLLATE in dump order; CREATE AS SELECT and unknown suffixes are rejected. MariaDB executable comments are rejected before the shared statement splitter can discard them. Profile consistency checks enforce positive integer byte/statement counters, raw byte equality to the source binding, a statement-count lower bound from indexed ordinals, nonblank source identity and the current format's unknown release. Exact decoded-byte and statement totals still require native audit; these invariants do not authenticate a coordinated rewrite of the entire index.
