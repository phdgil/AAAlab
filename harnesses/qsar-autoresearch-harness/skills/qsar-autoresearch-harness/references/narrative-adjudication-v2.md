# Candidate adjudication v2: isolated interface

This implementation is opt-in and not wired into `qsar_data.py`, runtime acceptance or preparation. It does not activate the proposed scientific amendment. Historical `Adjudication` and v1 artifact semantics remain unchanged. No real full-contract acceptance receipt has been produced by this implementation.

## Entry point and authority

`AdjudicationV2(config, entry, full_contract, accepted_contract_review, units, ledger_path)` accepts absolute `{path, sha256}` artifact descriptors. `entry` supplies the native HSDB `path`, `sha256` and `source_id`; this adapter does not claim support for other source schemas. Consume `rows()` completely before using its final summary. Partial yields and ledgers are diagnostic only. Recreate the instance for another pass.

`config` has exactly `schema_version: 2`, `inventory`, `decisions`, and `review_receipt`. Inventory uses the existing export format. The noncircular config digest includes schema_version and inventory/decisions descriptors, excluding review_receipt.

The **full contract**, not only data_curation, must contain:

```json
{"scientific_policy":{"narrative_adjudication_v2":{"schema_version":2,"clauses":{
  "stable_clause_id":{"disposition":"scientific_quarantine","reason":"critical_original_tested_identity_ambiguity"}
}}}}
```

`clauses` maps stable accepted clause IDs to exactly `disposition` and `reason`. Put explanatory policy text outside this executable node. The engine rejects contracts without this node, including unchanged v3. Quarantine reasons are enumerated in `QUARANTINE_REASONS_V2`; exclusions in `EXCLUSION_REASONS_V2`. A recognized reason still requires a matching clause in the accepted full contract. There is no generic conflict, parser-failure, missing-study-ID or duplicate-uncertainty quarantine.

The contract acceptance **adapter envelope** has exactly: `schema_version:2`, `stage:"contract"`, `status:"PASS"`, `contract_sha256`, `candidate`, `review_evidence`, `producer_execution_id`, distinct `reviewer_execution_id`, `receipt_writer`, `attestation:"local_leader_attested_not_authenticated"`, and empty `findings`. `candidate` is a bound JSON artifact containing `contract` equal to the full-contract descriptor. Both candidate and returned review evidence are revalidated. This is a small integration interface, not an alternative runtime review mechanism. The leader must construct it only from an actual independently accepted full-contract candidate and current runtime evidence. Proposal approval is insufficient.

The adjudication review receipt has the same identity/attestation/status/evidence fields, plus `contract_sha256`, `accepted_contract_review_sha256`, `source_id`, `source_sha256`, `inventory_sha256`, `decisions_sha256`, `config_sha256`, `code_hashes` (existing `code_hashes()` result), `accepted_policy_clauses` (exact full clause map) and `review_scope`. Scope is a list containing exactly one `{field_id, candidate_ids, examined_field_ids}` per inventory field. Candidate IDs are sorted. Field-list order is immaterial; the context list matches the decision exactly. Each receipt binds every decision and candidate, including zero-candidate fields and unresolved dispositions. PASS here means the reported disposition/accounting was reviewed; a reviewed unresolved candidate remains blocking.

## Field and candidate schema

Each decision is `{schema_version:2, field_id, action:"candidate_dispositions", reason, evidence, coverage, candidates}`. Evidence is a nonempty list of existing exact `{field_id,start,end,quote}` spans. Coverage is exactly `{candidate_enumeration:"complete"|"unresolved", examined_field_ids, remaining_coverage_issues, remaining_policy_issues, no_candidate_review}`. Issue lists contain nonempty text. All same-document native fields, including context-only fields, must be examined to claim complete review. Missing review remains visible and blocking; unknown or cross-document context IDs reject. Terminal exclusions or quarantines require complete source review. Empty candidates cannot close a field with a conservative scalar parser candidate. For nonempty candidate lists, `no_candidate_review` must be null. To close an empty list, it must instead contain exactly `{conclusion:"no_measurement_candidates", evidence, rationale}` with source spans and nonempty rationale. Empty lists for other fields require this independent exhaustive enumeration judgment and exact receipt scope; no lexical algorithm proves that judgment.

Every candidate has `candidate_id`, `measurement_id`, `population_id`, `measurement_evidence`, `population_evidence`, `population_scope`, `disposition`, and nonempty `reason`. `population_scope` contains exactly species, sex, strain and study_id, each a source span or null. All populated spans must belong to the same document; curation scope must match the observation population properties after whitespace/case normalization and missing-marker normalization (including -1 and n.a.). `candidate_ids_v2(field,candidate)` binds measurement identity to native source hash/ID and exact measurement anchor. Population identity binds that measurement to the supported explicit male/female partition, or unspecified for all other sex scopes. It never derives identity from the freely selected `population_evidence` supporting anchor. Changing that anchor between species and sex, rationale, disposition, or list ordering cannot change IDs. Measurement evidence belongs to the decided field. Population evidence remains same-document; curation observations must use that exact supporting anchor for species, sex or strain. Every candidate appears once and carries exactly its disposition-specific fields:

- `curation_candidate`: `observation`, validated using the existing strict observation schema. Its value anchor must match measurement evidence. Rows carry all three stable IDs; ordinary downstream scientific eligibility/identity/material checks remain necessary.
- `unresolved`: nonempty `remaining_issues`. Emits zero rows and blocks required-source coverage.
- `excluded`: `policy_clause_id`, `review` containing nonempty `evidence`, `rationale`, `reopening_trigger`. Emits zero rows.
- `scientific_quarantine`: `policy_clause_id` and typed `review`. Emits zero rows; sibling curation candidates survive.

Critical identity/numeric/censor/denominator/basis quarantine review has exactly `evidence`, `alternatives`, `resolution:"irreconcilable"`, `same_measurement_population:true`, `reopening_trigger`. At least two distinct alternatives are required, each `{interpretation,evidence}` with source spans. Different populations or studies are not automatically conflicts; source-based independent review must substantiate the same-measurement assertion.

`unavailable_critical_metadata` review instead has exactly `missing_property`, `indispensable_property`, `evidence`, `reviewed_assets`, `attempts`, `competing_interpretations`, `remaining_uncertainty`, `reopening_trigger`, and true `extraction_complete`, `context_complete`, `support_complete`, `linkage_complete`. Missing property is only `route` or `indispensable_experiment_linkage`. Indispensable property is `route`, `acute_context`, `tested_material` or `target`; missing route must name route. `reviewed_assets` contains source-version-bound `{path,sha256,source_id}` descriptors including the native asset, rechecked after iteration. Attempts and competing interpretations are nonempty text lists with concrete locators/joins documented in the bound independent review evidence. Missing study ID (including -1), uncertain duplication or unproven independence alone cannot satisfy this schema. A new applicable crosswalk/source release requires a new review/receipt; the integration layer must invalidate old evidence when known applicable inputs change, since this engine cannot discover undeclared new assets.

## Accounting and limits

The ledger preserves decisions, all candidate evidence, native record/locator, complete same-document context and emitted observation IDs. Counts separately report documents, source fields, context-only fields, decided fields, candidates, emitted observations, disposition counts, unreviewed fields, unresolved coverage fields, unresolved policy cases, scientific quarantine candidates and scientific issue reasons. Final booleans are `field_accounting_complete`, `candidate_disposition_accounting_complete`, `source_review_complete`, `required_source_coverage_complete`. No v1 completeness flag or all-science-complete claim is synthesized. Coverage is false until iteration and all final hash checks complete. Unresolved sibling decisions block coverage even when eligible rows were emitted.

Hashes, exact scopes, independent identity strings and nonempty evidence enforce provenance and recorded assertions, not exhaustive interpretation or scientific truth. Coordinated false assertions require independent scientific review to detect. The integration must reconcile these candidate IDs to downstream retained/excluded/quarantined observation membership, require zero training membership for holds, bind all assets to runtime dispatch, and enforce coverage at PASS, prerequisite reuse and preparation. None of those integrations is silently activated here. Synthetic tests exercise the structural contract only.

## Independent-review repair: population overlap

The initial implementation was rejected by independent engineering review: changing a female population anchor to the species span could let the same measurement be both held and emitted. The revised candidate artifact requires `population_scope` on every disposition, with deterministic IDs and an overlap guard covering curation, quarantine, exclusion and unresolved candidates alike. This is a candidate artifact change requiring fresh decisions and receipts; the executable scientific contract clause schema is unchanged. Historical v1 behavior is unchanged.

Within one field, overlapping measurement intervals cannot receive multiple compatible population dispositions. An unspecified, pooled or unknown sex scope overlaps every specific sex scope. Only explicit male versus female proves disjointness in this bounded adapter. Raw species, strain and study strings are never proof of distinct populations: Rat/Rattus norvegicus and SD/Sprague Dawley can be aliases; -1, blanks and n.a. are missing study identity. These properties and their source evidence remain preserved and checked against emitted observations, but do not create alternative record identities or bypass holds. All candidate checks complete before that field emits any rows.

Separate measurement anchors retain independent observations, including distinct studies. Expansion of one shared scalar into distinct strains/studies/species without explicit male/female separation is conservatively rejected: supporting such expansion needs a separately reviewed population partition/crosswalk interface. No equivalence ontology or new scientific clause is inferred here. Likewise the engine cannot discover semantically duplicate measurements in nonoverlapping source passages: those remain part of source-based independent review.

## Target-origin supplement: typed assertions, not keyword inference

The new excluded reason `nonexperimental_target` requires its own clause in the accepted full contract, such as `v4_nonexperimental_target`. Earlier contracts without that clause cannot authorize it; unchanged v3 cannot use v2 at all. This extension does not activate any contract or classify real source records.

Candidates may carry `target_origin`. It is mandatory for `excluded/nonexperimental_target` and optional on ordinary candidates without a specific origin question. Its common keys are exactly `classification`, `subtype`, nonempty exact-span `evidence`, and `binding`. Binding contains exactly `chemical`, `row`, `column`, `endpoint`, `species`, `route`, `value`, `unit`, `modifier`. Chemical, row, column and value are mandatory source spans. Other binding fields may be null when genuinely unreported; field/context review remains required for terminal decisions. Value must equal the candidate measurement anchor and the same-field row span must contain it. All spans are checked against the same native document. Independent review establishes the semantic relationship between chemical, row, column and origin assertion; equal numeric values do not establish column linkage.

- `classification: nonexperimental` uses subtype `qsar_prediction`, `read_across`, `model_prediction`, or `computed_toxicity_prediction`. It is allowed only for an authorized `excluded/nonexperimental_target` candidate, which emits zero rows. Its ordinary terminal `review` remains `{evidence,rationale,reopening_trigger}`. A source-proven prediction does not need a known route, species or unit to be excluded from experimental-target use. Nulls remain null; no oral exposure is inferred.
- `classification: origin_unknown` or `origin_conflict` uses `subtype: null`. It is allowed only for `unresolved`, with the same classification as candidate reason and an explicit matching entry in `remaining_issues`. Such cases emit zero rows and block coverage. They cannot be silently included, affirmatively excluded, or routed through scientific/unavailable-route quarantine.
- `classification: experimental` uses subtype `reported_measurement`, `same_substance_mortality_estimate`, or `validated_experimental_transform`. It additionally requires nonempty `experimental_basis_evidence`, `estimation_method`, and `transformation`. Estimation methods are `none`, `probit`, `maximum_likelihood`, `up_and_down`, `other_statistical_mortality`; transformations are `none`, `unit`, `molar`, `logarithmic`. Mortality estimates require a non-none method, transforms require a non-none transformation, and plain reported measurements require both none. These are origin assertions, not newly implemented numerical transformations. Existing observation, qualifier, dimensional and eligibility checks remain applicable. Experimental origin cannot authorize nonexperimental exclusion, but can coexist with another justified hold.

For emitted curation candidates, origin binding must exactly match the observation's chemical subject, endpoint, species, route, value, unit and original modifier spans. The origin object is carried into the emitted row and ledger. Summary `target_origin_counts` separates classification/subtype counts; `exclusion_reason_counts` separately counts affirmative exclusions.

The engine does not infer nonexperimental origin from the words calculated, estimated or model, the project name TEST, absent study IDs, unavailable full text, or membership in a mixed table. Typed classification and source bindings must be independently reviewed. A dishonest or incorrect classification can still cite exact text: structural validation is not NLP interpretation, proof of column semantics, or authentication of scientific review. This extension does not implement retrieval exhaustion, new crosswalk discovery, target conversion or the runtime approval adapter. Those integration limits remain explicit.
