# Roles and handoffs

Use a small producer–reviewer pipeline. A native direct-communication team is optional; file-based handoffs work across agent runtimes. Role names describe responsibilities, not an installed model or claimed agent execution.

## Teaching editor / coordinator
Own audience, language, time, evidence, privacy, and final output. Decide what students must DO after each slide. Verify sources; keep the distinction between observation, hypothesis and conclusion. Read prior feedback before revising. Provide one current brief and evidence ledger. Run rendering, audit tools and protected-file checks. Resolve findings and publish only on explicit authorization.

Output to producer: brief, approved inputs, source IDs, protected paths, output directory, and acceptance criteria. Pass source files by path, not full private datasets in a chat message.

## Visual producer
Use an editing-capable agent (for example an executor role). Read the brief, playbook and prior source before touching the deck. Produce concise editable slides and a manifest; do not invent evidence or fill a stock layout with unnecessary text. Prefer large visual anchors and short action labels over prose. Check each change against the learning action and time budget.

Output to coordinator: generator/deck paths, manifest, unresolved data or rendering issues. Skip shared tests, gates and formatters: the coordinator runs them after integration. Never claim verification from the fact that a file was written.

## Independent learning/design reviewer
Use a separate read-only reviewer where available (for example an architect/reviewer role). Inputs: brief, evidence, manifest, contact sheet and full-size difficult slides. No file mutation, tests or formatting.

Ask:
1. Can a student with limited English spot the key message and action without reading a paragraph?
2. Does this slide need to exist before project work starts?
3. Does each layout fit its content, or is the content serving the template?
4. Do color changes emphasize meaning with readable contrast and redundant labels?
5. Are evidence, uncertainty and task instructions correct on the visible slide, not only in notes?
6. Can students actually begin the task with the files, links and search fields supplied?

Return only material slide-numbered findings, severity, and approve/revise verdict. Separate critical data errors from optional aesthetic preferences. Do not demand a new slide or layout merely for novelty. On a follow-up, resolve prior findings and inspect consequential changes; do not reopen settled choices without evidence.

## Execution record
Coordinator → producer → rendered artifact → reviewer → coordinator fixes → final rerender.
Record actual role execution and source/manifest versions. If independent review is unavailable, disclose self-review. Do not prescribe a model brand or claim Harness upstream was installed. Two review cycles are normally sufficient; unresolved scientific or privacy errors still block release.
