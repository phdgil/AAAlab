# 합성 평가 사례

아래 사례는 검증용으로 새로 만든 입력이다. 실제 연구 결과나 과거 세션의 인용이 아니다. 실행 결과를 기록하기 전에는 통과했다고 표시하지 않는다.

## 작성 스킬의 호출 경계

| 입력 | 기대 |
|---|---|
| 한국어 연구 보고서의 문장과 구성을 수정해줘 | reports.md 적용 |
| 논문 초록을 근거 중심으로 다듬어줘 | reports.md 적용 |
| 발표자료 제목과 시각 표현을 수정해줘 | slides.md 적용 |
| PPT 파일을 내용 변경 없이 PDF로 변환해줘 | 작성 기준 적용 제외 |
| 문서에서 날짜만 찾아줘 | 작성 기준 적용 제외 |
| Python 함수 문서를 작성해줘 | 작성 기준 적용 제외 |

## evolve의 호출 경계

| 입력 | 기대 |
|---|---|
| 이번 보고서 피드백을 작성 스킬에 반영해줘 | 기존 스킬 개선 |
| 발표자료 하네스의 반복 오류를 개선해줘 | 기존 스킬 개선 |
| korean-document-style 피드백 기록을 찾아 기준을 갱신해줘 | 상대 링크로 기록 탐색 |
| 새 연구 분야의 하네스를 처음 설계해줘 | 신규 설계 절차로 분리 |
| 현재 PPT를 PDF로 변환해줘 | evolve 적용 제외 |
| 보고서의 실험 결과만 요약해줘 | evolve 적용 제외 |

## 결과물 품질과 범위

1. 제목 “처리 시간이 증가하면 처리량이 감소합니다” → “처리 시간별 처리량”. 본문에서 비교 근거는 유지한다.
2. “참고용이며 정확성을 보장하지 않습니다”는 삭제한다. “측정 장비가 다른 표본은 비교에서 제외했다”처럼 해석에 필요한 조건은 유지한다.
3. 합성 집단 A의 성능이 높지만 포함 비율이 작다면 집단 정의·포함 비율·전체 결과를 함께 제시한다. 이를 무조건 “정확도 향상”으로 바꾸지 않는다.
4. 추가 자료를 통합하면 핵심 방법·그림·완료 결과를 본문·부록·제외에 대응시킨다. 과거 평가 설계를 현재 성과와 혼합하지 않는다.
5. 빨간 굵은 이탤릭 주석 검토와 수정 계획만 요청받으면 해당 주석을 확인하고 기준·계획을 갱신한다. 원본 PPT는 수정하지 않는다.
6. 매 슬라이드에 다른 색을 쓰라는 현재 요청이 있으면 설명할 수 있는 역할을 부여한다. 개인 기준으로 무채색만 강제하지 않는다.

## 다음 실행의 관찰 항목

동일 유형의 재수정 횟수, 필요한 근거의 누락 여부, 현재 요청 범위 준수를 기록한다. 결과가 개선됐다는 판단은 실제 산출물 검토와 반복 실행 근거가 있을 때만 남긴다.
